= git-merge-forward

A zsh plugin that merges a chain of branches forward across git worktrees, with pre-flight remote syncing and interactive conflict resolution.

== Overview

This plugin automates the common "merge forward" workflow used in projects that maintain multiple long-lived version branches (e.g., merging fixes from 5.8.x into 6.0.x into 6.1.x into main). It is worktree-aware: if any of the branches involved are checked out in separate `git worktree` directories, each git operation runs in the correct directory automatically, and the tool clearly reports which directory is being used at every step.

== Features

* Merges a chain of branches in order: current branch -> branch1 -> branch2 -> ... -> branchN
* Worktree-aware: resolves the correct directory for every branch via `git worktree list --porcelain`, and always prints which directory each step runs in
* Pre-flight sync: fetches the remote once and syncs every branch in the chain with `<remote>/<branch>` before any merging starts
  ** Behind only -> fast-forwarded silently
  ** Missing locally -> created from the remote
  ** Ahead of (or diverged from) the remote -> pauses, shows the differing commits, and lets you reset to the remote or resolve it elsewhere and recheck, before continuing
* Refuses to touch a dirty working tree (no auto-stash) -- you clean it up, then re-run
* On merge conflict: reports the exact conflicted directory and the exact commands to run, then blocks and waits for you to resolve
* Resume validation: re-checks that the conflict was actually resolved and committed before continuing to the next hop
* Force-continue escape hatch and Ctrl+C abort, matching the interactive style of `merge-dependency-upgrades`

== Installation

Can be installed using antigen:

[source,bash]
----
antigen bundle rwinch/zsh-plugins git-merge-forward
----

Or manually by adding the plugin directory to your `PATH`.

== Usage

[source,bash]
----
git merge-forward --remote REMOTE BRANCH1 [BRANCH2 ...]
----

=== Options

* `--remote`, `-r REMOTE` - Remote to sync from before merging (required)
* `--help` - Display help message

=== Examples

[source,bash]
----
# Merge current branch -> 6.0.x -> 6.1.x -> main, syncing against origin first
git merge-forward --remote origin 6.0.x 6.1.x main

# Using the short flag
git merge-forward -r upstream release/6.1.x main
----

== Requirements

* Must be run from within a git repository
* The specified remote must exist
* Every worktree/directory touched by the merge chain must have a clean working tree (no auto-stash is performed)
* Git worktree support (Git 2.5+)

----

⚠️  '6.0.x' has diverged from 'origin/6.0.x' (1 ahead, 0 behind) (dir: /Users/rwinch/code/spring-security)

a1b2c3d a fix that hasn't been pushed yet

[Enter=recheck after resolving elsewhere / r=reset to remote / Ctrl+C=abort]
