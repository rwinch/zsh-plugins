= git-branches-release

A zsh plugin that rebuilds `release/<version>` branches on top of their disclosure branch, and creates the ones that do not exist yet. It never pushes: it prints the `git push --atomic` commands.

== Features

* `git branches-release 7.0.1,7.0.1.1` rebuilds each existing `release/<version>` as its base disclosure branch plus the commits that are only on the remote release branch (`git rebase --onto`). That needs a force push, so the printed command carries a lease.
* A release branch that exists nowhere is created from its base disclosure branch and pushed plainly (no force, no lease)
* A hotfix version (`7.0.1.1`) is based on `disclosure/active/<major>.<minor>.x`. Every other version is based on `disclosure/frozen/<major>.<minor>.x`.
* `--dry-run` validates and prints what would happen, and changes nothing
* It never fetches or pulls: run link:../fetch[git-branches-fetch] and link:../pull[git-branches-pull] first
* Everything is validated before anything changes, and all problems are reported together
* If nothing needs rebuilding it says `Everything is up to date, nothing to rebase.` and exits 0
* A rebase conflict stops at a prompt with the exact commands to resolve it

== Installation

[source,bash]
----
antigen bundle rwinch/zsh-plugins git-branches/release
----

Or manually by adding the plugin directory to your `PATH`.

The plugin also defines the alias `gbbr` for `git-branches-release`. See link:../README.adoc#aliases[the group README] for how the `gbb` prefix avoids alias collisions.

To fill in the versions, use the `ghmr` function of link:../../gh-milestones[gh-milestones] (this month's OSS milestones and next month's commercial hotfixes as a comma separated list):

[source,bash]
----
gbbr $(ghmr)
----

== Usage

[source,bash]
----
git branches-release [OPTIONS] VERSION[,VERSION ...]
----

[%header,cols="2,1,6"]
|===
| Option | Short | Description
| `--dry-run` | `-n` | Validate and print what would happen. Nothing is changed, and it exits 0.
| `--pause` | `-P` | After each release, stop so that the result can be validated, and say which directory to do it in.
| `--help` | `-h` | Display the help message.
|===

== Versions

* `<major>.<minor>.<patch>`, optionally followed by `.<hotfix>`, `-RC<n>` or `-M<n>`. An RC or M version must have patch `0`.
* At most one version per base branch: one hotfix and one non-hotfix per generation.
* A version whose generation has no disclosure branches maps to the `main` disclosure branches, but only when it is the next generation after the newest existing one (`7.1.0` when `7.0.x` is the newest). A skipped minor or major, or several new generations, is an error.

== Validation

Nothing changes until all of this passes. Problems are collected and reported together.

. Every base branch exists locally and has an upstream that still exists on the remote
. Every worktree that will be touched is clean (untracked files count), and has no merge, rebase or cherry-pick in progress
. Every base branch equals its upstream, as of the last fetch. Push a base branch that is ahead first.
. An existing release branch has no merge commits among its release-only commits (a rebase would flatten them), and a local copy equals the remote one (link:../pull[git-branches-pull] fast-forwards one that is only behind)
. A release branch that exists locally but not on the remote is an error. Delete the local one to have it created from its base.

== Example

[source,text]
----
$ git branches-release --dry-run 7.0.1,7.0.1.1,7.1.0
Plan:
  release/7.0.1   on disclosure/frozen/7.0.x  would rebase 2 commit(s) [commercial]
  release/7.0.1.1 on disclosure/active/7.0.x  up to date [commercial]
  release/7.1.0   on disclosure/frozen/main   would create from commercial/disclosure/frozen/main
        (no 7.1.x branch, newest generation)

Dry run, nothing changed.

$ git branches-release 7.0.1,7.1.0
Rebasing release/7.0.1 onto disclosure/frozen/7.0.x ... done
Creating release/7.1.0 from commercial/disclosure/frozen/main ... done

Done. Push when ready:
  git push --atomic commercial \
    +release/7.0.1 release/7.1.0 --force-with-lease=release/7.0.1:3f9a1c2
----

There is one push command per remote, because `--atomic` cannot span remotes.
