= git-worktrees-create

A zsh plugin that automates the creation of git worktrees for version branches and special branches.

== Overview

This plugin provides a command to automatically create git worktrees for all matching branches from a remote repository. It's particularly useful for projects that maintain multiple version branches (e.g., 5.8.x, 6.0.x, 6.1.x) and need to work on them simultaneously.

== Features

* Takes the branches to process as shell globs or literal branch names (e.g., `main`, `release/*`, `[0-9]*.[0-9]*.x`, `disclosure/*`)
* `gwwca` runs the usual patterns against the `commercial` and `oss` remotes
* Creates worktrees in the parent directory (`../branch-name`), also when run from a worktree of a slashed branch such as `release/1.0` or from a subdirectory
* Automatically creates local tracking branches if they don't exist
* Skips branches that are already checked out in a worktree, and existing worktrees, with informative messages
* Validates git repository and remote existence before processing
* Ends with `Done, N failed` and exit status 1 if a branch or worktree could not be created, and warns when no branch matches the patterns

== Installation

Can be installed using antigen:

[source,bash]
----
antigen bundle rwinch/zsh-plugins/git-worktrees-create
----

Or manually by adding the plugin directory to your `PATH`.

== Usage

The plugin also defines the alias `gwwc` for `git-worktrees-create`, and the function `gwwca`, which runs it twice, commercial first:

. `--remote commercial` with `[0-9]*.[0-9]*.x`, `disclosure/*` and `release/*` (skipped with a message if that remote does not exist)
. `--remote oss` with `[0-9]*.[0-9]*.x`, `main` and `docs-build`

Commercial runs first, so a `.x` branch that exists on both remotes comes from commercial and the oss run skips it, because its worktree exists. `gwwca` accepts `--oss-remote REMOTE` and `--commercial-remote REMOTE` to use other remote names, and `--dry-run`, which is passed to both runs.

[source,bash]
----
git-worktrees-create --remote REMOTE [OPTIONS] PATTERN [PATTERN ...]
----

Quote globs so the shell does not expand them. `*` also matches `/`, so `disclosure/*` covers `disclosure/CVE-2025-1234/5.8.x`. At least one pattern is required.

=== Options

* `--remote REMOTE` - The remote to create worktrees from (required)
* `--name-prefix PREFIX` - Prepend `PREFIX` to the local branch name and the worktree directory, for a remote whose branch names clash with local ones (`commercial/docs-build` becomes `commercial-docs-build`)
* `--skip-missing-remote` - If the remote does not exist, say so and exit 0
* `--dry-run` - Show what would be created without fetching or creating anything (uses the branches already fetched)
* `--help` - Display help message

=== Examples

[source,bash]
----
# Create worktrees for main and the release/* branches of the oss remote
git-worktrees-create --remote oss 'release/*' main

# Use 'upstream' as remote
git-worktrees-create --remote upstream '[0-9]*.[0-9]*.x' 'disclosure/*'

# Worktree for docs-build of the commercial remote, as commercial-docs-build
git-worktrees-create --remote commercial --name-prefix commercial- docs-build
----

== Behavior

The command performs the following steps:

1. Validates you're in a git repository
2. Checks that the given remote exists
3. Fetches the latest changes from the remote
4. Iterates through all remote branches
5. For each branch matching one of the patterns:
   * Checks if the branch is already checked out in a worktree, or a worktree already exists at `../branch-name`
   * If not:
   ** Creates a local tracking branch if it doesn't exist
   ** Creates a worktree at `../branch-name`

== Requirements

* Must be run from within a git repository
* The specified remote must exist
* Parent directory (`../`) must be writable
* Git worktree support (Git 2.5+)
